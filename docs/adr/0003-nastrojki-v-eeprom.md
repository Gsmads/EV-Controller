# ADR-0003: Настройки в EEPROM, изменяемые по UART без перепрошивки

**Статус:** принято
**Дата:** 2026-05-11

## Контекст
Значительная часть параметров определяется только на реальной машине
с реальным ребёнком: комфортный темп разгона, максимальная скорость
для каждого режима, мёртвая зона моторов, коэффициенты усилителя руля,
пороги защиты по току. Подбирать их перепрошивкой — значит каждый раз
нести машину к компьютеру.

## Решение
Все настраиваемые параметры собираются в структуре `settings_t`, которая
хранится в EEPROM с магическим числом, версией раскладки и CRC16.

При старте структура читается; при несовпадении magic, версии или CRC
происходит откат к заводским значениям. Изменение параметра по UART
пишет в ОЗУ, отдельная команда фиксирует в EEPROM.

## Последствия
- Настройка ведётся на площадке из веб-интерфейса, без компьютера.
- Повреждение EEPROM не приводит к непредсказуемому поведению —
  происходит откат к заведомо безопасным значениям.
- Разделение «применить» и «сохранить» позволяет пробовать значение
  на ходу и откатиться выключением питания.
- Появляется обязанность версионировать раскладку и писать миграции.
- Ресурс EEPROM конечен (около 100 тыс. циклов), сохранение нужно
  ограничивать по частоте.

## Отклонённые варианты
| Вариант | Почему отклонён |
|---|---|
| Константы в коде | Каждая правка — перепрошивка; настройка на площадке невозможна |
| Хранить настройки на ESP32 | Arduino должен работать и без связи; при потере ESP32 остался бы без параметров |
| EEPROM без CRC | Повреждение одной ячейки дало бы, например, нулевой темп торможения |

## Проверка
Тест `test_cfg_settings.c`: сохранение и чтение, порча байта данных
приводит к откату на заводские значения, размер структуры помещается
в EEPROM с запасом.
