# ADR-0012: Веб-интерфейс на vanilla JS с абстрактным транспортом

**Статус:** принято
**Дата:** 2026-06-11

## Контекст
Интерфейс нужен сейчас для отладки с компьютера через USB, а в дальнейшем
должен работать на ESP32 и раздаваться машиной по WiFi, в том числе на
телефон. Владелец параллельно изучает веб-разработку.

## Решение
Vanilla JavaScript, модули ES6, без сборщика и фреймворка.

Три ядра — транспорт, протокол, состояние — и набор независимых виджетов.
Виджет подписывается на состояние и не знает о существовании других
виджетов. Транспорт скрыт за интерфейсом: сейчас это WebSocket к
Python-мосту, в дальнейшем — WebSocket напрямую к ESP32.

## Последствия
- Файлы кладутся на ESP32 как есть, без шага сборки — существенно
  при ограниченном объёме файловой системы.
- Добавление функциональности — новый файл виджета, без правки остальных.
- Смена транспорта затрагивает один файл.
- Код понятен без знания фреймворка, что соответствует задаче обучения.
- Плата за это: часть работы, которую фреймворк делает сам,
  придётся писать руками — реактивность реализована подпиской на
  состояние вручную.

## Отклонённые варианты
| Вариант | Почему отклонён |
|---|---|
| React или Vue | Требуют сборки; результат тяжёл для файловой системы ESP32 |
| Alpine.js или Lit | Легче, но добавляют зависимость ради задачи, которая решается подпиской в тридцать строк |
| Готовая панель (Grafana, Node-RED) | Не размещается на ESP32; не даёт нужного циферблата |

## Проверка
Замена транспорта на заглушку не требует правок в виджетах.
Общий объём статических файлов помещается в файловую систему ESP32.
