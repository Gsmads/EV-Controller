# ADR-0017: Изменяемая константа живёт в настройках, а не в коде

**Статус:** принято
**Дата:** 13.09.2026
**Заменяет:** —
**Заменён:** —

## Контекст

Решение владельца: «все изменяемые константы надо заводить в настройки, это
позволит проще делать и дебаг и настройку, без перепрошивок и перезапусков
сервера в том числе».

Повод конкретный. В `CLAUDE.md` §8 шесть параметров помечены как выдуманные —
`ENCODER_PULSES_PER_REV`, `WHEEL_DIAMETER_MM`, калибровка педалей,
`motor_deadzone`. Настоящие значения добываются замерами на железе: прокрутить
колесо на оборот и посчитать импульсы, найти минимальный ШИМ, при котором
колесо трогается. Это работа в несколько итераций. Сегодня половина из них
живёт в `cfg_board.h`, то есть каждая итерация — перепрошивка; на стороне
моста то же самое решается перезапуском `server.py` с другим ключом.

Механизм для прошивки уже спроектирован — ADR-0005 «Реестр параметров как
единый контракт»: таблица дескрипторов в PROGMEM, запись и чтение по
идентификатору вместо смещения, валидация по диапазону, генерация описания
для веба из одного источника. Он лежит в статусе «предложено» и не
реализован. Решение владельца делает его обязательным.

Бюджет памяти под это есть:

| Ресурс | Всего | Занято настройками | Остаток |
|---|---|---|---|
| RAM | 2048 | 182 (8,9 %) | 1866 |
| EEPROM | 1024 | 188 (18,4 %) | 836 байт, то есть ещё 418 полей `uint16` |
| PROGMEM под реестр | 32768 | 0 | 50 параметров — 600 байт (1,8 %) |

## Решение

**Правило.** Константа, значение которой уточняется опытом — калибровка,
порог, коэффициент, темп, таймаут, выбор поведения, — объявляется параметром
настроек, а не числом в коде. И в прошивке, и в `tools/gui`.

**Механизм в прошивке — ADR-0005.** Его статус переводится в «принято»
настоящим решением: реестр дескрипторов, доступ по идентификатору, валидация
по диапазону в одном месте, генерация контракта для веба. Без реестра правило
неисполнимо: `SET_PARAM` по сырому смещению не умеет ни проверять диапазон,
ни отдавать вебу имена полей.

**Что настройкой не становится.** Граница проходит по признаку «это свойство
конструкции, а не опыта»:

| Не настройка | Почему |
|---|---|
| Назначение выводов `cfg_board.h` | Свойство разведённой платы. Меняется перепайкой, а не вебом |
| Выбор таймеров | ADR-0010; меняет работу ШИМ и системного тика целиком |
| Размеры буферов `RX/TX_BUFFER_SIZE` | Компоновка RAM известна на этапе сборки; динамическое выделение запрещено (`CLAUDE.md` §3 правило 5) |
| `SETTINGS_MAGIC`, `SETTINGS_VERSION`, версия протокола | Описывают сам формат настроек. Параметр, меняющий раскладку, в которой он лежит, — рекурсия |
| Размер и раскладка `settings_t` | То же самое |

**Отдельный класс: параметры, ошибка в которых отнимает канал управления.**
Скорость UART — единственный такой параметр сегодня. Записанная неверно, она
отнимает тот самый канал, через который её можно исправить: плата отвечает на
250000, веб спрашивает на 9600, и починить нечем, кроме перепрошивки. Правило
на такие параметры: **изменение допускается только вместе с названным путём
восстановления**. Какой это путь — открытый вопрос, см. ниже; до его закрытия
скорость остаётся константой сборки (ADR-0015).

**На стороне моста.** `tools/gui/server.py` держит свои константы в ключах
командной строки — скорость, порт, частота опроса. Правило то же: значение,
которое подбирают, меняется из интерфейса и переживает перезапуск, а ключ
командной строки остаётся как способ подключиться к плате с другими
настройками. Ключ — аварийный вход, а не штатный способ настройки.

## Последствия

**Что становится проще.** Итерация настройки на площадке перестаёт стоить
перепрошивки. Замеры из `CLAUDE.md` §8 можно снимать и подставлять в том же
цикле, в котором они получены. Появление нового параметра — строка в описании,
а не правка JavaScript и прошивки одновременно.

**Что становится сложнее.** Растёт поверхность, через которую можно испортить
поведение машины, в которой ездит ребёнок. Отсюда обязательность валидации по
диапазону из ADR-0005 и флага `REQUIRES_STOP` для параметров, которые нельзя
менять на ходу. Правило «значение вне диапазона — `NACK`, настройки не
изменились» перестаёт быть пожеланием.

**Что мы обязаны поддерживать.**
- Каждый новый параметр приходит с диапазоном и умолчанием. Параметр без
  диапазона не добавляется: проверять его будет нечем.
- Каждое расширение `settings_t` поднимает `SETTINGS_VERSION` и приносит
  миграцию. Иначе первый запуск после обновления сбросит калибровку, добытую
  замерами.
- `PROTO_MAX_PAYLOAD` = 60 меньше, чем `sizeof(settings_t)` = 182: читать
  настройки одним пакетом нельзя ни сейчас, ни потом. Чтение идёт по
  параметрам или страницами — это отмечено ещё в ADR-0005.

**Чего решение не даёт.** Оно не превращает выдуманные значения в измеренные.
`ENCODER_PULSES_PER_REV = 12` и `WHEEL_DIAMETER_MM = 200` останутся выдуманными
и после переезда в настройки — просто менять их станет дешевле. Пока они не
замерены, зависящие от них функции считаются непроверенными, как и написано
в `CLAUDE.md` §8.

## Открытый вопрос

Скорость UART как настройка требует названного пути восстановления. Варианты
описаны владельцу; до ответа скорость остаётся константой сборки. Решение
оформляется отдельным ADR и ссылается на этот.

## Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Оставить как есть: константы в коде | Каждая итерация подбора — перепрошивка. Шесть параметров из `CLAUDE.md` §8 подбираются замерами, то есть не с первого раза |
| Перенести всё подряд, включая пины и таймеры | Настройка, меняющая назначение вывода, не описывает реальность: провод от этого не переедет. Зато позволяет из веба подать ШИМ на вход. Граница проведена выше |
| Файл конфигурации на SD вместо EEPROM | Новая внешняя зависимость и новый режим отказа (карта вынута, файл побит) ради задачи, которую EEPROM решает: занято 18,4 %, свободно 836 байт |
| Записывать настройки в EEPROM при каждом изменении | Ресурс EEPROM — 100 000 циклов на ячейку. Подбор коэффициента крутилкой в вебе израсходовал бы его за один вечер. Сохранение остаётся явной командой, как в ADR-0003 |
| `SET_PARAM` по смещению, как сейчас, но с диапазонами в вебе | Два источника истины. Прошивка примет `brake_rate_max = 0` от любого другого клиента и сохранит в EEPROM — то есть отключит тормоз. Валидация обязана быть на той стороне, которая исполняет |

## Проверка

1. Тест: запись значения вне диапазона возвращает `NACK` с кодом «вне
   диапазона», `settings_t` не изменилась, EEPROM не тронута.
2. Тест: чтение параметра по идентификатору возвращает то же значение, что
   было записано; идентификатор неизвестного параметра даёт `NACK`.
3. Тест: настройки прошлой версии читаются после миграции, калибровка педалей
   сохранена, новые поля получили умолчания.
4. CI: сгенерированные из описания файлы совпадают с лежащими в репозитории.
5. Наблюдаемо: значение `motor_deadzone`, изменённое из веба, вступает в силу
   без перепрошивки и переживает перезагрузку контроллера после явного
   сохранения.
