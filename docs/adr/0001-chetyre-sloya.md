# ADR-0001: Четырёхслойная архитектура с изоляцией платформы

**Статус:** принято
**Дата:** 2026-05-11

## Контекст
Прошивка пишется под ATmega328P, но владелец допускает переезд на STM32
или ESP32. Одновременно нужна возможность тестировать логику на десктопе:
проверять рампу, кривые педалей и PID без стенда с моторами.

Если обращения к регистрам размазаны по всему коду, ни то ни другое
невозможно.

## Решение
Четыре слоя, зависимости строго вниз:

```
app_*  →  svc_*  →  drv_*  →  hal_*  →  железо
```

Весь платформозависимый код собирается в единственном файле
`hal_<platform>.cpp`. Слои выше него компилируются обычным `g++`
без каких-либо заголовков AVR.

## Последствия
- Переезд на другой микроконтроллер — замена одного файла.
- Бизнес-логика тестируется на десктопе с моками HAL.
- Появляется накладной расход: вызов через функцию HAL вместо прямой
  записи в регистр. На частотах нашего цикла (100 Гц) несущественно.
- Требуется дисциплина: правило «нет `Arduino.h` вне HAL» легко нарушить
  случайно, поэтому оно проверяется сторожем в CI, а не памятью.

## Отклонённые варианты
| Вариант | Почему отклонён |
|---|---|
| Писать сразу под конкретное железо | Переезд означал бы переписывание; логику нельзя протестировать без стенда |
| Использовать готовый HAL (Arduino Core, HAL ST) | Тянет за собой модель памяти и тайминги конкретной платформы; не решает задачу десктопных тестов |
| Три слоя без драйверов | Свойства платы (передаточная функция ОУ, инверсия оптопар) пришлось бы держать в бизнес-логике |

## Проверка
Сторож в CI: `Arduino.h`, `avr/*` не встречаются нигде, кроме
`firmware/hal_atmega328p.cpp`. Намеренное нарушение роняет сборку.
