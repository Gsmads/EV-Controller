# ADR-0018: Собственный драйвер UART вместо адаптации Grbl

**Статус:** принято
**Дата:** 13.09.2026
**Заменяет:** —
**Заменён:** —

## Контекст

`firmware/MICRO_UART.*` — адаптация `serial.c` из [Grbl](https://github.com/gnea/grbl).
Работа над очередью 0 `docs/AUDIT.md` упёрлась в этот файл трижды.

**Он платформенный, но лежит вне платформенного файла.** `MICRO_UART.cpp`
обращается к `UCSR0A`, `UCSR0B`, `UBRR0H`, `UBRR0L`, `UDR0`, `F_CPU` и
определяет `ISR(SERIAL_RX)` / `ISR(SERIAL_UDRE)`, не включая ни `avr/io.h`,
ни `avr/interrupt.h`: их тянул `Arduino.h` через `MICRO_UART.h:22`. Проверка
по дереву: регистры ATmega328P трогают ровно два файла — `hal_atmega328p.cpp`
(законно по ADR-0001) и `MICRO_UART.cpp` (нет).

**Из-за этого он непроверяем.** Замена `Arduino.h` на `<stdint.h>` — а больше
заголовку ничего не нужно, в нём из Arduino используется только `uint8_t` —
немедленно даёт `error: 'F_CPU' was not declared`, `'UCSR0A' was not declared`,
`'UBRR0H' was not declared`. То есть собрать модуль на десктопе нельзя, а
`CONVENTIONS.md` требует красный тест до исправления дефекта. Очередь 0
(B-1 — TX-буфер, B-2 — сентинел 0xFF) и политика переполнения из ADR-0016
проверялись бы только на железе.

**Слои через него нарушены в обе стороны.** `PRINT.cpp` и `app_debug.cpp`
вызывают `serial_write()` напрямую, минуя `hal_uart.h`. Файл слоя `app_*`
обращается к драйверу, минуя HAL, — запрет `CLAUDE.md` §3 правило 2.

При этом целевой интерфейс уже объявлен: `firmware/hal_uart.h` описывает
`hal_uart_init(uint32_t baud)`, `hal_uart_write`, `hal_uart_read`,
`hal_uart_available`, `hal_uart_flush_rx`, `hal_uart_set_rs485_tx`.
Сегодня `hal_atmega328p.cpp` реализует их поверх `serial_*` — то есть
прослойкой над чужим драйвером, который делает ровно то же самое.

## Решение

`MICRO_UART.*` удаляются. UART пишется заново и раскладывается по слоям:

| Что | Где | Проверяется |
|---|---|---|
| Кольцевой буфер: индексы, заполненность, свободное место, политика переполнения | `util_ring` — переносимый модуль, без платформы | десктопным тестом `g++` |
| Регистры, делитель UBRR, обработчики прерываний, управление направлением RS485 | `hal_atmega328p.cpp` | только на железе |
| Интерфейс | `hal_uart.h`, без изменений в составе функций | — |

`PRINT.cpp` и `app_debug.cpp` переводятся на `hal_uart_write()`. Прямых
вызовов `serial_*` в проекте не остаётся.

**Заодно закрывается B-2.** `hal_uart_read()` сегодня возвращает `uint8_t`
и не может сообщить «данных нет» иначе, чем значением 0xFF — сентинел
`SERIAL_NO_DATA`, унаследованный из Grbl, где по UART шёл ASCII. В бинарном
протоколе 0xFF — обычный байт данных. Новый интерфейс: `int16_t hal_uart_read(void)`,
−1 означает «пусто». Это то самое исправление, которое `docs/AUDIT.md`
предлагает вторым пунктом очереди 0.

**Лицензия.** После удаления `MICRO_UART.*` в репозитории не остаётся кода,
производного от Grbl. GPL v3 (ADR-0013) при этом сохраняется: лицензия
выбрана осознанно, а не вынужденно, — это прямо записано в ADR-0013.
Указание на Grbl в `README.md` убирается вместе с кодом, потому что
описывает то, чего больше нет.

## Последствия

**Что становится проще.** Очередь 0 становится проверяемой на десктопе:
кольцевой буфер и политика переполнения — обычный модуль под `g++`. Красный
тест для B-1 и B-2 наконец есть где написать. Исключение сторожа для
`MICRO_UART.h` и `MICRO_UART.cpp` снимается, список ADR-0014 сокращается.
Обещание «переезд на другую платформу — замена одного файла» становится
верным: сегодня оно неверно, потому что платформенных файлов два.

**Что становится сложнее.** Мы берём на себя код, который в Grbl отлаживали
годами на тысячах станков. Смягчающее обстоятельство: именно в этой копии он
уже сломан — из `serial_write` удалена проверка переполнения (B-1), а сентинел
0xFF несовместим с бинарным протоколом (B-2). То есть наследуется не
проверенный временем код, а его испорченная версия.

**Что мы обязаны поддерживать.** Кольцевой буфер покрывается тестами до
написания платформенной части, а не после: заполнение, опустошение,
переполнение на границе, обе политики ADR-0016, счётчик потерь. Обработчики
прерываний тестируются только на железе — это записано в `CONVENTIONS.md`
и не меняется.

**Чего решение не даёт.** Оно не проверяет ничего на железе. Пока замеры
`HARDWARE_BRINGUP.md` не сняты, новый драйвер — такой же непроверенный
черновик, как и старый, только разложенный по слоям и покрытый десктопными
тестами.

## Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Разделить существующий файл: буфер наружу, регистры в HAL | Меньше работы, но результат — тот же код Grbl, разрезанный пополам, с обоими дефектами внутри. Править их всё равно пришлось бы, а разрез по живому коду сложнее проверять, чем новый модуль с тестами |
| Признать `MICRO_UART.cpp` вторым платформенным файлом | Дёшево сейчас: добавить `avr/io.h` и исключение в ADR. Но очередь 0 осталась бы непроверяемой на десктопе, а утверждение `README.md` о замене одного файла при переезде стало бы ложным официально |
| Взять чистый `serial.c` из Grbl заново | Вернуло бы проверку переполнения (B-1), но не решило бы ни сентинел 0xFF, ни расположение вне HAL, ни прямые вызовы из `app_*`. И оставило бы производный код с его происхождением |
| Взять `HardwareSerial` из ядра Arduino | Прямо противоречит ADR-0002: ядро Arduino не используется, в том числе в HAL. Плюс динамическая инициализация и лишние килобайты флеша |
| Оставить как есть до появления железа | Железо не сделает модуль проверяемым: оно даст замеры, а не тесты. Дефекты B-1 и B-2 надо чинить сейчас, и чинить вслепую — ровно то, от чего предостерегает `SLICE_0_PLAN.md`: «сначала проверки, потом исправления» |

## Проверка

1. `grep -rn "serial_write\|serial_read\|MICRO_UART" firmware/` не находит ничего.
2. `tools/ci/check_layer_boundaries.py all` зелёный без исключений для
   `MICRO_UART.h` — запись удалена из списка ADR-0014.
3. `tools/ci/check_modules_compile.sh`: `MICRO_UART.cpp` исчез из списка
   пропущенных, новый переносимый модуль компилируется.
4. Красный тест B-1: запись пакета 41 байт в заполненное кольцо не затирает
   ранее записанные байты. До правки — падает.
5. Красный тест B-2: байт 0xFF проходит через буфер и читается как 0xFF,
   а признак «данных нет» отличим от него. До правки — падает.
6. На железе: мост принимает сто пакетов телеметрии подряд без ошибок CRC.
