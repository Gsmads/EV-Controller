# ADR-0005: Реестр параметров как единый контракт прошивки и веба

**Статус:** предложено
**Дата:** 2026-09-09

## Контекст
Текущая запись настроек идёт по сырому смещению в структуре:
`SET_PARAM(offset, size, data)` с проверкой только на выход за границы.
Из этого следуют три проблемы:

1. Нет валидации по смыслу. Запись `brake_rate_max = 0` отключает тормоз
   и сохраняется в EEPROM.
2. Нет команды чтения настроек. Вкладку настроек в вебе построить нечем:
   форму невозможно заполнить текущими значениями.
3. Смещения дублируются в вебе. Добавление поля в середину `settings_t`
   молча ломает клиент.

## Решение
Ввести таблицу дескрипторов параметров, размещённую в PROGMEM:

```c
typedef struct {
    uint16_t id;        // стабильный идентификатор, не смещение
    uint16_t offset;
    uint8_t  type;      // u8 / u16 / i16 / enum
    int32_t  min, max;
    uint8_t  flags;     // REQUIRES_STOP | READONLY | NEEDS_SAVE
} param_desc_t;
```

Запись и чтение идут **по идентификатору**, не по смещению. Прошивка
валидирует значение по этой же таблице. Веб запрашивает таблицу
и генерирует форму сам.

Таблица и её отражение для веба **генерируются из одного описания**
(`params.yaml`) на этапе сборки. Сгенерированные файлы помечаются `.gen`
и не правятся руками; CI проверяет их актуальность.

## Последствия
- Одна охраняемая дверь для настроек: валидация в одном месте.
- Форма настроек в вебе обновляется добавлением параметра в описание,
  без правки JavaScript.
- Рассинхронизация схемы становится невозможной по построению.
- Флаг `REQUIRES_STOP` решает вопрос параметров, которые нельзя менять
  на ходу — например частоты ШИМ.
- Цена: около 12 байт PROGMEM на параметр (при 50 параметрах — 600 байт
  из 32 КБ) и появление шага генерации в сборке.
- Читать 182 байта настроек одним пакетом нельзя: `PROTO_MAX_PAYLOAD` = 60.
  Нужно чтение по параметрам либо страницами.

## Отклонённые варианты
| Вариант | Почему отклонён |
|---|---|
| Оставить запись по смещению | Нет валидации; клиент ломается молча при изменении структуры |
| Имена и диапазоны только в вебе | Два источника истины; при добавлении параметра веб покажет `param_37` |
| Имена и диапазоны только на МК | Около 1 КБ PROGMEM на строки, при этом дублирования всё равно не избежать в подписях интерфейса |

## Проверка
Тест: запись значения вне диапазона возвращает `NACK` и не меняет
настройки. CI: сгенерированные файлы совпадают с результатом генерации
из описания.
