# ADR-0011: Бинарный протокол с CRC16 вместо текстового

**Статус:** принято
**Дата:** 2026-05-12

## Контекст
Обмен между ESP32 и Arduino идёт по RS485 рядом с мощными моторами.
Требуется передавать телеметрию с частотой около 10 Гц и принимать
команды управления, в том числе критичные к задержке.

## Решение
Пакет фиксированной структуры:

```
[0xAA] [LEN] [CMD] [PAYLOAD...] [CRC16_L] [CRC16_H]
```

CRC16-CCITT по `LEN + CMD + PAYLOAD`. Разбор — конечным автоматом,
побайтно, без блокировок.

## Последствия
- Помеха на линии приводит к отбрасыванию пакета, а не к исполнению
  искажённой команды.
- Пакет телеметрии компактен: 36 байт данных против нескольких сотен
  в текстовом виде.
- Разбор не требует буфера строки и работает в потоке.
- Отладка сложнее, чем у текстового протокола: нужен инструмент.
  Частично компенсируется тем, что отладочный текст не начинается
  с байта синхронизации и может сосуществовать в том же порту.
- Требуется одинаковая реализация CRC на трёх языках — C, Python,
  JavaScript. Совпадение проверено на эталонных векторах.

## Отклонённые варианты
| Вариант | Почему отклонён |
|---|---|
| Текстовый протокол в стиле G-code | Избыточен по объёму; разбор чисел из строки на AVR дорог; помеха может дать синтаксически верную команду |
| Modbus RTU | Тяжелее, чем нужно; неудобен для потоковой телеметрии |
| Без контрольной суммы | Рядом с моторами искажённая команда исполнилась бы как настоящая |

## Проверка
Эталонные векторы CRC совпадают в реализациях на C, Python и JavaScript.
Тесты разбора: битая контрольная сумма, обрыв пакета, мусор перед
байтом синхронизации, значение длины вне диапазона.
