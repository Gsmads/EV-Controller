# ADR-0020: Основной код называет сигналы, слой железа их привязывает

**Статус:** принято
**Дата:** 13.09.2026
**Заменяет:** —
**Уточняет:** ADR-0009

## Контекст

ADR-0009 перенёс номера каналов АЦП в настройки: соответствие сигналов входам
определяется тем, как легли провода при монтаже, и по схеме не восстанавливается.
Реализация сделала это буквально — `svc_pedals` читает из настроек номер канала
и передаёт его в `hal_adc_read()`:

```c
const settings_t *cfg = cfg_settings_get();
gas.adc_channel   = cfg->adc_ch_pedal_gas;
...
p->raw = hal_adc_read(p->adc_channel);
```

Слой сервисов оперирует **номером канала АЦП** — величиной, которая существует
только потому, что внизу стоит ATmega328P. На STM32 это будет другая нумерация,
на внешнем АЦП по SPI — третья. Переносимость держится на одном файле HAL ровно
до тех пор, пока номера не начали расходиться по сервисам.

Владелец сформулировал правило: «в основном коде используем унифицированные
названия, а в слое Hardware назначаем связку между реальным железом и
абстрактными функциями доменного уровня; тогда переезд на новый контроллер
приведёт просто к замене папки с железом».

## Решение

Основной код обращается к **сигналу по имени**, а не к каналу по номеру.

`hal_adc.h` объявляет перечень аналоговых сигналов системы:

```c
typedef enum {
    ANALOG_PEDAL_GAS = 0,
    ANALOG_PEDAL_BRAKE,
    ANALOG_CURRENT_RIGHT,
    ANALOG_CURRENT_LEFT,
    ANALOG_STEERING_POS,
    ANALOG_SIGNAL_COUNT
} analog_signal_t;

uint16_t hal_adc_read_signal(analog_signal_t signal);
```

Привязка сигнала к каналу живёт в слое железа и задаётся при инициализации
из настроек — так сохраняется то, ради чего ADR-0009 и принимался: ошибка
монтажа исправляется из веба, а не паяльником.

```c
void hal_adc_bind(analog_signal_t signal, uint8_t channel);
```

**Перечень сигналов — доменное понятие, и это не нарушение слоёв.** HAL не
вызывает сервисы и ничего о них не знает; он лишь объявляет, какие сигналы
умеет отдавать. Это обычная роль поддержки платы: наверх — имена, вниз —
регистры. Обратная зависимость по-прежнему запрещена.

**Номер канала остаётся в настройках**, но его читает только слой железа при
привязке. Сервисы поля `adc_ch_*` больше не видят.

Правило распространяется на всю периферию по мере её появления: дискретные
входы панели, выходы драйверов, каналы ШИМ. Везде наверх уходит имя функции,
вниз — привязка.

## Последствия

**Что становится проще.** `svc_pedals` перестаёт знать, что под ним АЦП
с восемью каналами: он читает «педаль газа». Переезд на другой контроллер
перестаёт требовать правок в сервисах.

**Что становится сложнее.** Появляется таблица привязки, которую надо
инициализировать до первого чтения. Непривязанный сигнал обязан быть
отличимым состоянием, а не нулём: чтение до инициализации — ошибка порядка
запуска, и она должна быть видна, а не выглядеть как отпущенная педаль.

**Что мы обязаны поддерживать.** Перечень сигналов и таблица привязки
меняются вместе. Сигнал, добавленный в перечень и не привязанный, — тот же
молчаливый отказ, что и раньше.

**Чего решение не даёт.** Оно не делает переезд «заменой одной папки»: файлы
прошивки лежат плоско, потому что этого требует Arduino IDE (`CLAUDE.md` §4).
Каталог с платформой — отдельный шаг, и он упирается в систему сборки,
а не в расположение кода. Записано как открытый вопрос.

## Отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Оставить как есть: сервис читает номер канала из настроек | Номер канала — платформенное понятие. Сегодня оно в одном сервисе, завтра в трёх, и обещание «переезд — замена одного файла» перестаёт быть правдой незаметно |
| Перечень сигналов в отдельном заголовке вне HAL | Лишний уровень: перечень нужен ровно двум сторонам — тому, кто читает, и тому, кто привязывает. Объявление рядом с функцией чтения честнее описывает, что HAL умеет |
| Привязка константами в `cfg_board.h` вместо настроек | Отменяет ADR-0009: ошибка монтажа снова лечилась бы перепрошивкой. Провода переставляют чаще, чем перепрошивают |
| Возвращать из `hal_adc_read_signal` признак «не привязано» отдельным кодом | Значение уходит в калибровочную формулу педали; любой признак вне диапазона прошёл бы как «педаль в полу». Непривязанный сигнал даёт 0 и увеличивает счётчик — так же, как недопустимый канал |

## Проверка

Таблица привязки лежит в слое железа, а он по `docs/CONVENTIONS.md`
проверяется только на железе. Поэтому проверки разделены честно.

**Десктопом:**

1. `grep -rn "adc_ch_\|hal_adc_read(" firmware/svc_* firmware/app_*` не находит
   ничего: номера каналов остались в настройках и слое железа.
2. Тест `svc_pedals` с моком `hal_adc_read_signal`: сервис запрашивает
   именно `ANALOG_PEDAL_GAS` и `ANALOG_PEDAL_BRAKE` и не обращается
   к номерам каналов.
3. Привязка вызывается до первого чтения — проверяется порядком вызовов
   в `setup()`, а не тестом.

**На железе (`docs/HARDWARE_BRINGUP.md`):**

4. Чтение сигнала после привязки даёт значение того канала, к которому он
   привязан: подать известное напряжение на вход и сверить.
5. Перепривязка сигнала из веба меняет источник данных без перезагрузки.
6. Непривязанный сигнал даёт 0 и увеличивает счётчик — проверяется
   намеренным пропуском привязки.
