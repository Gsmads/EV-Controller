# Техническое задание: контроллер детского электромобиля

## 1. Обзор проекта

Проект представляет собой систему управления детским электромобилем с дистанционным контролем через WiFi. Ключевая концепция: ребёнок самостоятельно управляет машиной (педали, руль, кнопки), а родитель использует смартфон/ноутбук для:

- настройки характеристик автомобиля (макс. скорость, отзывчивость педалей, режимы);
- мониторинга состояния (заряд аккумулятора, ток моторов, скорость колёс);
- разблокировки автомобиля паролем (защита от угона);
- удалённого аварийного вмешательства (мягкая остановка, ограничение скорости).

Классический радиопульт сознательно не используется — телефон всегда под рукой, а WiFi позволяет реализовать богатый веб-интерфейс и работать как со смартфона, так и с ноутбука при отладке.

## 2. Архитектура системы

Система состоит из **двух физически разделённых блоков**, связанных шиной RS485:

### Блок 1 — Коммуникационный контроллер (ESP32)
- WiFi (AP + STA);
- веб-интерфейс / мобильное приложение;
- связь с BMS по UART (телеметрия аккумулятора);
- управление светотехникой, поворотниками, парктрониками;
- алгоритм помощи при движении (использование парктроников для предотвращения столкновений);
- защита от несанкционированного запуска (пароль).

### Блок 2 — Контроллер автомобиля (Arduino Nano + драйверы)
- управление моторами задних колёс;
- электроусилитель руля;
- считывание педалей газа и тормоза;
- управление режимами движения;
- передача телеметрии в Блок 1.

**Связь между блоками:** RS485 (полудуплексная, дифференциальная, помехоустойчивая — оптимально для машины с сильными электромагнитными помехами от моторов).

**Приоритет команд:** команды UART/RS485 имеют **более высокий приоритет**, чем аппаратные входы. Пример: педаль газа нажата, но по UART пришла команда STOP — машина останавливается.

## 3. Блок 1 — Коммуникационный контроллер (ESP32)

### 3.1 Режимы WiFi

Контроллер должен поддерживать **два режима работы**, переключаемых из настроек:

- **AP (Access Point)** — для работы в полевых условиях со смартфона ребёнка/родителя. SSID и пароль настраиваются.
- **STA (Station)** — для отладки с ноутбука через домашнюю сеть.
- **Гибридный режим (AP+STA)** — желательно поддержать; ESP32 это умеет аппаратно.

### 3.2 Веб-интерфейс / API

- Веб-страница, размещённая в SPIFFS/LittleFS ESP32 (HTML/CSS/JS, без внешних CDN — должно работать без интернета).
- WebSocket для real-time телеметрии (скорость, ток, заряд) — обновление 5–10 Гц.
- REST API для команд и настроек (мощность, профиль педалей, лимиты).
- Возможность OTA-обновления прошивки обоих блоков (для ESP32 нативно, для Arduino — через RS485-загрузчик, опционально).

### 3.3 Защита от несанкционированного запуска

- При включении зажигания контроллер находится в **заблокированном состоянии**.
- Разблокировка происходит после ввода пароля в приложении (или подтверждения на «доверенном» устройстве, MAC которого сохранён).
- В заблокированном состоянии Блок 2 не получает команды на старт; силовое питание моторов отключено.
- Опционально: NFC-метка/брелок для быстрой разблокировки без телефона.

### 3.4 Связь с BMS

- UART, протокол уточняется по модели BMS (часто Daly, JBD/Xiaoxiang — есть открытые спецификации).
- Считываются: напряжение пакета, напряжения банок, ток заряда/разряда, температура, SOC.
- Данные транслируются в веб-интерфейс и в Блок 2 (для адаптации мощности при низком заряде).

### 3.5 Управление периферией (на ESP32)

Идея перевесить всю периферию на ESP32 — **архитектурно правильная**, потому что:

- эта периферия не требует жёсткого реал-тайма;
- разгружает Arduino Nano (у него и так дефицит пинов);
- позволяет управлять светом/звуком/поворотниками из веб-интерфейса.

К ESP32 через 8-канальный MOSFET-модуль (Optocoupler Isolation PWM Control) подключаются:

| Канал | Назначение |
|-------|-----------|
| CH1   | Передние фары (ближний свет) |
| CH2   | Передние фары (дальний свет / ДХО) |
| CH3   | Задние фары (габариты) |
| CH4   | Стоп-сигналы |
| CH5   | Левый поворотник (перед+зад параллельно) |
| CH6   | Правый поворотник |
| CH7   | Звуковой сигнал / клаксон |
| CH8   | Резерв (фара заднего хода / салонная подсветка) |

Поскольку модуль умеет PWM, фары можно диммировать (ДХО ≠ ближний свет реализуется одним каналом с разной яркостью).

**Поворотники без рычагов:** реализовать кнопками на руле или сенсорными точками на корпусе руля. Альтернатива — управление с телефона (для родителя в режиме «контроля») или автоматическое включение поворотника при существенном повороте руля (по углу с энкодера).

### 3.6 Парктроники

Стандартные ультразвуковые парктроники для автомобилей обычно работают по **аналоговому или ШИМ-выходу с длительностью импульса, пропорциональной расстоянию**, либо по UART с собственным протоколом. Манчестерское кодирование встречается у некоторых модулей, но это нужно подтвердить осциллографом по конкретной модели. Реальный протокол **уточнить замером** до написания кода.

Рекомендую как fallback-вариант рассмотреть HC-SR04 / JSN-SR04T (водозащищённые) — простой trigger/echo, легко интегрируется.

### 3.7 Алгоритм помощи при движении (ADAS-lite)

Парктроники используются для:

**Аварийное торможение спереди:** при сближении со стеной на скорости — плавное снижение скорости пропорционально расстоянию.

```
distance > 200 cm  → ограничений нет
distance 100-200 cm → soft warning (звуковой сигнал, мигание)
distance 50-100 cm  → плавное снижение макс. скорости (множитель 0.3-0.8)
distance < 50 cm    → принудительная остановка (UART STOP)
```

**Помощь при повороте:** если при повороте вправо правый передний парктроник видит резкое сближение — подруливание влево или остановка. Реализуется как корректирующая команда в шину RS485.

**Парктроник задний:** при движении назад работает аналогично; звуковая сигнализация частотой, пропорциональной близости.

**Важно:** все эти функции должны быть **отключаемыми** из веб-интерфейса (отладка, парковка вплотную).

## 4. Блок 2 — Контроллер автомобиля

### 4.1 Состав

| № | Плата | Назначение |
|---|-------|-----------|
| 1 | Arduino Nano | Основной контроллер |
| 2 | ZS-X11H (×2) | Драйверы мотор-колёс (правое и левое заднее) |
| 3 | BTS7960 | Драйвер электроусилителя руля |
| 4 | XFW-HX711 + тензодатчик | Датчик усилия на руле (для EPS) |

### 4.2 Электроусилитель руля (EPS)

Сохранён штатный DC-мотор с редуктором, который шёл с автомобилем. Управляется драйвером BTS7960.

**Обратная связь:**

- **Положение руля** — датчик Холла на валу рулевой рейки/колонки, аналоговый выход на A3 (0–1023, центр ≈ 512).
- **Усилие** — тензодатчик (Load Cell) через HX711 (D5 = DOUT, D12 = SCK), измеряющий силу, с которой ребёнок поворачивает руль.

**Принцип работы:** ребёнок крутит руль с малым усилием, EPS усиливает это движение, поворачивая колёса. PID-регулятор стремится свести фактическое положение колёс к заданному рулём.

### 5.2 HC595 — управление дискретными сигналами драйверов

Сдвиговый регистр (8 выходов), управляемый по SPI с CS = D8.

| Выход | Назначение |
|-------|-----------|
| Q0 | Поворот руля вправо (R_EN BTS7960) |
| Q1 | DIR правого мотора (направление вращения) |
| Q2 | STOP правого мотора (0 = свободное вращение) |
| Q3 | BRAKE правого мотора (1 = блокировка) |
| Q4 | DIR левого мотора (направление вращения) |
| Q5 | STOP левого мотора (0 = свободное вращение) |
| Q6 | BRAKE левого мотора (1 = блокировка) |
| Q7 | Поворот руля влево (L_EN BTS7960) |

**Схема управления BTS7960 для EPS:** ШИМ-сигнал с D6 подаётся **одновременно на оба входа** L_PWM и R_PWM драйвера BTS7960. Направление вращения управляется дискретными сигналами Q0 (R_EN, вправо) и Q7 (L_EN, влево) — активируя соответствующий полумост. В каждый момент времени активен только один из Q0/Q7, второй в нуле.

## 6. Функциональные требования

### 6.1 Управление моторами колёс

#### Сигналы драйвера ZS-X11H

| Сигнал | Уровень | Действие |
|--------|---------|---------|
| DIR | 0 / 1 | Направление вращения |
| BRAKE | 1 | Активная блокировка (короткое замыкание обмоток) |
| STOP | 0 | Отключение драйвера, свободное вращение |
| PWM | 0–1023 | Управление скоростью |

#### Безопасное переключение состояний

При смене любого из сигналов DIR / BRAKE / STOP контроллер **обязан**:

1. Плавно снизить PWM до 0 (с заданной скоростью замедления, см. §6.2);
2. Дождаться полной остановки мотора (проверка по датчику скорости);
3. Только после этого изменить сигнал DIR / BRAKE / STOP;
4. Дополнительная пауза 50–100 мс для устаканивания тока в обмотках;
5. Затем разрешить плавный набор PWM (если требуется движение).

Это критично — переключение направления на полном ходу либо сожжёт драйвер, либо повредит редуктор.

#### Профиль разгона и торможения

Скорость — целевое значение в диапазоне **0–1023**, источник — педаль газа (A0) или команда UART.

- **Разгон:** ШИМ нарастает от текущего значения к целевому с заданной скоростью (`accel_rate`, ШИМ/сек). При достижении целевой скорости — удержание.
- **Замедление:** при снижении целевого значения ШИМ падает с заданной скоростью (`decel_rate`). При целевой скорости = 0 — мотор плавно тормозит до нуля, затем по необходимости включается BRAKE.
- Скорости `accel_rate` и `decel_rate` зависят от **режима вождения** (см. §6.4).

#### Настраиваемая частота ШИМ

Частота ШИМ моторов колёс **зависит от режима вождения** и настраивается через веб-интерфейс. Наблюдение: при медленной езде (низкий PWM, высокий требуемый момент) пониженная частота ШИМ обеспечивает лучший крутящий момент на старте. При высокой скорости — более высокая частота снижает шум и нагрев.

**Подход к реализации:**

1. Начальный этап: фиксированная частота (например, 8 кГц) для всех режимов.
2. Расширенный этап: профиль частоты ШИМ, привязанный к режиму вождения (настройка из веб-интерфейса).

| Режим | Рекомендуемый диапазон частот | Примечание |
|-------|------------------------------|-----------|
| Eco | 4–8 кГц | Приоритет — момент на малых оборотах |
| Normal | 8–12 кГц | Баланс между моментом и шумом |
| Sport | 12–18 кГц | Приоритет — плавность и тишина |

**Аппаратные ограничения Arduino Nano (ATmega328P, 16 МГц, Timer1):**

- Phase-correct PWM, 10 бит: f = 16 МГц / (2 × 1024) ≈ **7,8 кГц** (максимум при 10-битном разрешении).
- Phase-correct PWM, 9 бит: f = 16 МГц / (2 × 512) ≈ **15,6 кГц**.
- Fast PWM, 10 бит: f = 16 МГц / 1024 ≈ **15,6 кГц**.
- Fast PWM, 9 бит: f = 16 МГц / 512 ≈ **31,3 кГц**.

При необходимости динамически менять частоту — переключать режим и TOP-значение Timer1 через регистры ICR1/TCCR1A/TCCR1B. Перенастройка частоты должна происходить **только при PWM = 0** (моторы остановлены), чтобы избежать глитчей.

**Важно:** конкретные оптимальные частоты для каждого режима определяются экспериментально; веб-интерфейс должен позволять менять их с шагом 1 кГц и отслеживать влияние на ток/скорость через телеметрию.

#### Считывание скорости колёс

- Прерывания на D2 (правое) и D3 (левое).
- Счётчик импульсов за фиксированный интервал (например, 100 мс) → перевод в RPM или линейную скорость.
- Передача в UART после каждого измерения.
- Используется также для функций ABS-lite и контроля устойчивости (§9).

#### Защита по току

- Чтение A2/A6 с частотой ≥100 Гц.
- При превышении порога `I_max` — **снижение PWM** (не моментальное отключение, чтобы не было рывков).
- При длительном превышении `I_max_peak` (несколько секунд) — переход в аварийный режим, отключение силового питания через PCA9535.
- Передача тока в UART (5–10 Гц).

### 6.2 Тормозная система

**Источник:** педаль тормоза на A1, значения 0–1023.

**Логика:**

1. Тормоз имеет **приоритет** над газом. При одновременном нажатии — действует тормоз.
2. PWM моторов плавно снижается со скоростью, пропорциональной нажатию тормоза (`decel_rate = f(brake_pedal)`).
3. После остановки (скорость колёс ≈ 0):
   - если педаль тормоза **отпущена** — сигнал BRAKE НЕ активируется (свободное вращение);
   - если педаль тормоза **остаётся нажатой** — активируется сигнал BRAKE до отпускания педали.

**Расширения (см. §9):**
- Стоп-сигналы загораются автоматически при `decel_rate > порог` или активном BRAKE;
- Удержание на склоне (hill-hold) — BRAKE удерживается короткое время после остановки.

### 6.3 Управление рулём (PID-регулятор EPS)

#### Концепция

Электроусилитель руля работает по следующей схеме:

1. Ребёнок прилагает усилие к рулю — это усилие читается тензодатчиком (HX711).
2. Магнитный энкодер фиксирует положение руля (или вала колёс).
3. PID-регулятор подаёт PWM на BTS7960, помогая повернуть руль в сторону приложенного усилия, либо удерживая колёса в заданном положении.

#### Параметры PID

- **Источник ошибки:** аналоговый вход A3 — желаемое положение vs фактическое. Целевое значение ≈ 512 (центр).
- **Выход PID:** PWM 0–1023 на D6.
- **Направление вращения:** Q0 (R_EN) и Q7 (L_EN) на HC595 управляют полумостами BTS7960. ШИМ подаётся на оба входа L_PWM и R_PWM одновременно.

#### Формула направления

```
error = target (512) - measured_position (0..1023)

if error > 0:
    direction = LEFT  → Q7 (L_EN) = 1, Q0 (R_EN) = 0
else:
    direction = RIGHT → Q0 (R_EN) = 1, Q7 (L_EN) = 0

PWM на D6 = abs(PID_output)  // 0..1023, подаётся на оба L_PWM и R_PWM
// Активный полумост определяется Q0/Q7
```

#### Адаптивность EPS

- При высокой скорости движения усилие EPS уменьшается (тяжелее руль) для безопасности.
- При низкой скорости / парковке — увеличивается (легче руль).
- Параметры PID (Kp, Ki, Kd) настраиваются из веб-интерфейса.

### 6.4 Режимы вождения

Режим выбирается дискретными входами SW1_4–SW1_6 на PCA9535 либо командой UART.

| Режим | Макс. скорость | accel_rate | decel_rate | Реверс | Особенности |
|-------|---------------|-----------|-----------|--------|-------------|
| **Locked** | 0 | — | — | — | До ввода пароля |
| **Neutral** | 0 | — | — | — | STOP активен, моторы свободно крутятся |
| **Handbrake** | 0 | — | — | — | BRAKE активен |
| **Eco / Forward 1** | 30–40% | медленный | плавный | нет | Для самых маленьких / в помещении |
| **Normal / Forward 2** | 70% | средний | средний | нет | Базовый дневной режим |
| **Sport / Forward 3** | 100% | быстрый | резкий | нет | Для опытного ребёнка на улице |
| **Reverse** | 30% | медленный | плавный | да | Низкий лимит, активирует фару заднего хода и звуковой сигнал |
| **Parent / Remote** | задаётся по UART | по UART | по UART | по UART | Полное удалённое управление с телефона |

**Переходы между режимами:**

- Любой переход «forward ↔ reverse» **обязательно** через полную остановку (см. §6.1).
- Переход «handbrake → forward» — только при отпущенной педали газа (защита от рывка).
- Переход в «locked» (потеря связи с Блоком 1) — мягкая остановка с `decel_rate` Eco-режима.

### 6.5 Поведение при потере связи (watchdog)

- Если по RS485 не пришло ни одной команды за **N миллисекунд** (например, 500 мс) — Блок 2 переходит в **fail-safe**: плавное замедление до нуля + переход в Neutral.
- После восстановления связи — ждёт явной команды от Блока 1 для возобновления движения.
- Watchdog Arduino (8 сек) должен быть включён для защиты от зависания.

## 7. Протокол связи UART/RS485

### 7.1 Параметры

- Скорость: 115 200 бод (запас по скорости + надёжность);
- Формат: 8N1;
- Полудуплекс, управление DE/RE с D4;
- CRC16 в конце каждого пакета.

### 7.2 Команды от ESP32 к Arduino

| Команда | Параметры | Описание |
|---------|-----------|---------|
| SET_MODE | mode_id | Смена режима вождения |
| SET_SPEED | 0..1023 | Целевая скорость (переопределяет педаль) |
| SET_BRAKE | 0..1023 | Принудительное торможение |
| SET_STEER | -512..+512 | Целевое смещение руля от центра |
| SET_DIR | F / R / N | Направление |
| EMERGENCY_STOP | — | Немедленная мягкая остановка |
| LOCK / UNLOCK | password_hash | Блокировка/разблокировка |
| SET_PARAM | name, value | Калибровка (PID, лимиты, кривые педали, частота ШИМ) |
| GET_TELEMETRY | — | Запрос телеметрии (или авто-режим) |

### 7.3 Телеметрия от Arduino к ESP32 (5–10 Гц)

- Скорость правого/левого колеса (RPM);
- Ток правого/левого мотора (А);
- Положение руля;
- Состояние педалей (газ/тормоз);
- Текущий режим;
- Флаги ошибок (overcurrent, overheat, fail-safe, stall, etc.);
- Время работы (uptime).

## 8. Безопасность и отказоустойчивость

1. **Аппаратный E-Stop:** физическая кнопка на машине, разрывающая силовое питание моторов (минуя контроллер). Обязательна.
2. **Watchdog UART:** §6.5.
3. **Watchdog Arduino:** аппаратный, 8 сек.
4. **Защита по току:** §6.1.
5. **Защита по напряжению:** ESP32 читает напряжение пакета через BMS; при `V < V_cutoff` — принудительный Eco-режим, при `V < V_critical` — отключение.
6. **Защита по температуре:** опционально — термисторы на драйверах моторов и в BMS.
7. **Корректная обработка переключения DIR/BRAKE/STOP:** §6.1.
8. **Защита от угона:** пароль, шифрование WiFi (WPA2), уникальный пароль AP-режима для каждой машины.
9. **Логирование ошибок:** ESP32 пишет fault log в LittleFS (последние 100 событий).

## 9. Предложенные улучшения

### 9.1 Электронный дифференциал

Сейчас оба задних колеса вращаются с одинаковым PWM. На повороте внешнее колесо должно проходить больший путь — без дифференциала возникает проскальзывание. Имея независимое управление двумя моторами, можно реализовать **программный дифференциал**:

```
steering_angle = (current_steer_position - 512) / 512   // -1..+1
turn_factor = abs(steering_angle) * differential_gain    // 0..0.3 типично

if turning right:
    pwm_left  = pwm_base
    pwm_right = pwm_base * (1 - turn_factor)
if turning left:
    pwm_left  = pwm_base * (1 - turn_factor)
    pwm_right = pwm_base
```

Это даст более плавный поворот, меньший износ резины, меньшее потребление в поворотах.

### 9.2 Torque vectoring (опционально, продвинуто)

То же, но с учётом скорости каждого колеса по тахометру: подтормаживание внутреннего колеса для более острого вписывания в поворот. Лёгкая версия — увеличение скорости внешнего колеса при недостаточной поворачиваемости.

### 9.3 ABS-lite

При резком торможении контроллер уже мониторит скорость каждого колеса. Если одно из колёс резко теряет скорость относительно другого (проскальзывание) — кратковременное снижение тормозного усилия на этом колесе. Реализуется на той же логике, что и обычное торможение, без дополнительного железа.

### 9.4 Traction control

Симметрично ABS: при резком разгоне, если одно колесо «срывается» (скорость растёт быстрее ожидаемой), его PWM снижается.

### 9.5 Cruise control

В Forward 2 / 3 — фиксация текущей скорости (например, по двойному нажатию на кнопку газа или из приложения). Поддерживается до нажатия тормоза или явной отмены.

### 9.6 Soft start

В Eco-режиме первые 0.5 секунды после старта PWM растёт по квадратичной кривой — устраняет рывок.

### 9.7 Кривая отклика педали

В настройках — выбор кривой газа: линейная / квадратичная (более «спокойная» для маленьких) / S-образная. То же для тормоза.

### 9.8 Скоростное ограничение угла поворота

На высокой скорости ограничивать максимальное отклонение руля (анти-опрокидывание). На малой скорости — полный диапазон. Это особенно важно для детского автомобиля с высоким центром тяжести.

### 9.9 Автоматическое включение поворотников

При повороте руля более чем на N° — включение соответствующего поворотника. Выключение через 3 секунды после возврата к центру.

### 9.10 Автоматические стоп-сигналы

Загораются при `decel_rate > порог` или активном BRAKE — без отдельной педали или ручного управления.

### 9.11 Реверсный пищок

При движении назад — прерывистый звуковой сигнал, частота растёт при сближении с препятствием.

### 9.12 Геозона (если позже добавите GPS-модуль к ESP32)

В приложении задаётся радиус разрешённого передвижения от точки старта. При выходе за зону — принудительное снижение скорости и уведомление родителю.

### 9.13 Калибровка из приложения

- Калибровка нуля педалей (минимум и максимум);
- Калибровка центра руля;
- Тонкая настройка PID-коэффициентов EPS с графиком отклика;
- Тонкая настройка лимитов тока, скорости, ускорений по каждому режиму;
- Сохранение/загрузка профилей («утренний», «вечерний», «дача», «парк»).

### 9.14 Телеметрия и логирование

- График скорости, тока, заряда за последние N минут в веб-интерфейсе;
- Сохранение «поездок» с длительностью, средней скоростью, пробегом;
- Уведомление о низком заряде в push (если ESP32 подключён к домашнему WiFi и интернету);
- Учёт пройденного пути (одометр) на основании импульсов с датчиков колёс.

### 9.15 Аварийная диагностика (DTC-коды)

Список флагов ошибок с человекочитаемыми описаниями в приложении:
- E001: Overcurrent right motor
- E002: Overcurrent left motor
- E003: Steering stall (мотор руля не отзывается)
- E004: UART timeout
- E005: BMS communication lost
- E006: Battery low
- E007: Battery critical
- ...

### 9.16 «Родительский тормоз»

Большая красная кнопка в приложении — мягкая немедленная остановка по UART. Должна быть всегда видна на главном экране.

### 9.17 Параметрический звук двигателя (geek bonus)

Опционально — динамик в машине, имитирующий звук мотора с громкостью/тональностью, пропорциональными скорости и току. Делается на ESP32 через DAC / PWM. Можно загружать разные «движки» (электро, спорт, трактор).

### 9.18 Защита от случайной разблокировки пароля

Ограничение числа попыток ввода пароля; временная блокировка после N неверных попыток. Логирование попыток входа.

## 10. Конечная карта пинов Arduino Nano (с учётом исправлений)

```
D0  ← USB-UART RX + RS485 RO
D1  → USB-UART TX + RS485 DI
D2  ← INT0 (правый колёсный энкодер)
D3  ← INT1 (левый колёсный энкодер)
D4  → RS485 DE/RE
D5  ← HX711 DOUT (данные тензодатчика усилия на руле)
D6  → PWM EPS (Timer0)
D7  ← INT PCA9535 (прерывание расширителя портов)
D8  → HC595 CS / latch
D9  → PWM левый мотор (Timer1, настраиваемая частота)
D10 → PWM правый мотор (Timer1, настраиваемая частота)
D11 → SPI MOSI (HC595 data)
D12 → HX711 SCK (тактирование тензодатчика)
D13 → SPI SCK (HC595 clock)
A0  ← педаль газа
A1  ← педаль тормоза
A2  ← ток правого мотора
A3  ← положение руля (датчик Холла)
A4  ↔ I²C SDA (PCA9535)
A5  ↔ I²C SCL (PCA9535)
A6  ← ток левого мотора (только аналоговый)
A7  ─ резерв (только аналоговый)
```

## 11. Открытые вопросы для уточнения

### 11.1 Парктроник — протокол

Манчестерское кодирование — это предположение. **До написания кода парсинга** замерить осциллографом сигнал реального модуля. Возможные варианты:
- импульс с длительностью, пропорциональной расстоянию;
- UART с собственным протоколом;
- I²C;
- собственно манчестер (редко).

### 11.2 Энкодеры мотор-колёс — характеристики

Сколько импульсов на оборот колеса даёт ZS-X11H? Это нужно для:
- расчёта скорости в км/ч;
- определения частоты прерываний (загрузка CPU);
- оценки разрешающей способности на малой скорости.

### 11.3 Что делать с резервными выходами SW0_1 — SW0_5?

В описании их назначение не задано. Рекомендую: дублирование управления светотехникой как fallback (на случай если ESP32 «упадёт») — фары, стоп-сигналы, поворотники. Получится распределённая система: основное управление с ESP32, аварийное — с Arduino.

### 11.4 Резервные входы SW1_7 / SW1_8

Хорошие кандидаты на использование:
- физическая кнопка поворотника лево;
- физическая кнопка поворотника право;
- кнопка клаксона;
- кнопка фар.

### 11.5 Полная электрическая схема

Для окончательной верификации распиновки, проверки совместимости уровней напряжений (5В Arduino vs 3.3В датчик Холла / HX711), правильности подтяжек I²C и схемы обвязки BTS7960 — необходимо приложить полную схему контроллера (автор разрабатывал самостоятельно, схема будет добавлена позже).

## 12. Очерёдность реализации (рекомендация)

1. **MVP-1:** Arduino-контроллер с педалью газа, одним режимом движения, без EPS, без UART, без HC595/PCA9535 — просто два мотора и педаль. Цель — отладить ШИМ и торможение.
2. **MVP-2:** Добавление EPS с PID, обратной связью по положению.

4. **MVP-4:** UART/RS485, базовый протокол команд и телеметрии.
5. **MVP-5:** ESP32 с веб-интерфейсом, AP-режим, базовое управление.
6. **MVP-6:** BMS, защита паролем, OTA.
7. **MVP-7:** Парктроники и ADAS-функции.
8. **MVP-8:** Электронный дифференциал, ABS-lite, traction control.

На каждом этапе — проверка функционала и стабильности до перехода к следующему.
