# Сборка прошивки

Прошивка собирается **своим Makefile через avr-gcc, без ядра Arduino**
(ADR-0025). Arduino IDE тоже продолжает работать — но ядро ей больше не
нужно, и ничего из него прошивка не использует.

---

## Быстрый старт

```bash
sudo apt install gcc-avr avr-libc avrdude    # Debian/Ubuntu
cd firmware
make                                          # собрать и показать расход памяти
make flash PORT=/dev/ttyUSB0                  # прошить
```

Результат сборки:

```
AVR Memory Usage
Device: atmega328p

Program:    9454 bytes (28.9% Full)
Data:        918 bytes (44.8% Full)
```

Числа стоит смотреть каждый раз. Флеша 32 КБ, и запас там большой. **ОЗУ
всего 2 КБ**, из них почти половина уже занята статически — остальное
достаётся стеку. Это та величина, которую нельзя узнать постфактум, когда
прошивка перестанет помещаться.

---

## Что нужно установить

| Пакет | Зачем |
|---|---|
| `gcc-avr` | компилятор `avr-gcc` / `avr-g++` |
| `avr-libc` | стандартная библиотека для AVR, заголовки `avr/io.h` и прочие |
| `avrdude` | заливка прошивки в контроллер |

Проверка:

```bash
avr-gcc --version     # ожидается 7.3 или новее
avr-size --version
avrdude -v            # версия и список программаторов
```

На macOS: `brew tap osx-cross/avr && brew install avr-gcc avrdude`.
На Windows проще всего взять WSL и ставить как в Debian.

---

## Цели Makefile

| Команда | Что делает |
|---|---|
| `make` | собрать `.elf` и `.hex`, показать расход памяти |
| `make size` | только расход флеша и ОЗУ |
| `make flash` | залить прошивку через загрузчик |
| `make clean` | убрать каталог `build/` |
| `make help` | краткая справка |

Заливка:

```bash
make flash PORT=/dev/ttyUSB0 BAUD=57600     # стоковый загрузчик Nano
make flash PORT=/dev/ttyUSB0 BAUD=115200    # после прошивки optiboot
```

Стоковый Nano идёт со старым загрузчиком на 57600. `PORT`, `BAUD` и
`PROGRAMMER` переопределяются из командной строки, править Makefile не надо.

## Флаги сборки и почему они такие

```
-mmcu=atmega328p -DF_CPU=16000000UL -Os -std=c++11
-Wall -Wextra -Wundef -Wshadow
-ffunction-sections -fdata-sections  -Wl,--gc-sections
-fno-exceptions -fno-rtti -fno-threadsafe-statics
-flto
```

| Флаг | Зачем |
|---|---|
| `-Os` | оптимизация по размеру. На 32 КБ флеша и 2 КБ ОЗУ это не вкус, а необходимость |
| `-ffunction-sections -fdata-sections` + `--gc-sections` | каждая функция в своей секции, линковщик выбрасывает невызываемое |
| `-fno-exceptions -fno-rtti` | исключений и динамической типизации на AVR нет, а поддержка стоит килобайтов |
| `-fno-threadsafe-statics` | защита локальных статиков от гонок не нужна: потоков нет, а код защиты есть |
| `-flto` | межмодульная оптимизация: инлайн через границы файлов |
| `-Wundef` | неопределённый макрос в `#if` считается нулём молча. Опечатка в имени флага сборки иначе не видна |
| `-Wshadow` | локальная переменная, закрывающая другую, — источник правок «не в ту переменную» |

`F_CPU` обязателен: от него зависят расчёт делителя UART и задержки. Без
него `avr-libc` не соберёт `util/delay.h`.

## Что собирается

Все `.cpp` в `firmware/` плюс сам скетч `EV_Controller.ino`, который
компилируется как обычный C++ (`-x c++`).

Точка входа: Arduino IDE определяет макрос `ARDUINO` и приносит свой
`main()`, который зовёт `setup()` и `loop()`. При сборке Makefile ядра нет,
и `main()` берётся из хвоста самого `.ino` под `#ifndef ARDUINO`. Один файл
собирается обоими способами — раздваивать точку входа не пришлось.

---

## Сборка в Arduino IDE

Работает по-прежнему: открыть `firmware/EV_Controller.ino`, выбрать плату
Arduino Nano и процессор ATmega328P, нажать «Проверить».

Ядро при этом всё равно линкуется и занимает место, хотя прошивка из него
ничего не вызывает. Поэтому для реальной работы лучше Makefile — цифры
расхода памяти у него честные.

### Подкаталоги в Arduino IDE

Плоская структура `firmware/` — требование не Arduino вообще, а корня
скетча. Файлы в подкаталоге `<скетч>/src/` IDE собирает **рекурсивно**
(с версии 1.6.10). То есть `firmware/src/hal/`, `firmware/src/svc/` и так
далее работают и в IDE тоже.

Раскладка по слоям не сделана: это перемещение всех файлов разом, и делать
его заодно с правкой кода — значит получить diff, в котором ничего не
разобрать. Отдельным изменением, когда понадобится.

## Непрерывная интеграция

Сборка под ATmega328P идёт в CI (`.github/workflows/`) на каждый push и
каждый pull request, следом за десктопными тестами. Падение сборки под
целевой контроллер — красный CI.

Чего CI не проверяет и проверить не может:

- **исполнение**. Прошивка собирается и компонуется, но не запускается.
  Тайминги, регистры периферии, поведение watchdog — только на железе;
- **расход стека**. Линковщик считает статическое размещение, а глубину
  стека — нет. 918 байт статики оставляют около 1130 на стек, и следить
  за этим приходится глазами;
- **предупреждения не блокируют.** Сборка сегодня чиста на
  `-Wall -Wextra -Wundef -Wshadow`, но CI на предупреждениях не падает.

## Прошивка загрузчика optiboot

Нужна для аппаратного watchdog (ADR-0022): стоковый загрузчик Nano не
сбрасывает `WDRF`, и после первого же срабатывания watchdog плата уходит в
цикл перезагрузок, из которого по USB не выйти.

Потребуется программатор ISP — вторая плата Arduino с прошивкой
`ArduinoISP` подходит.

```bash
# 1. На плату-программатор залить скетч ArduinoISP (есть в примерах IDE)
# 2. Соединить: MISO-MISO, MOSI-MOSI, SCK-SCK, 5V-5V, GND-GND,
#    вывод 10 программатора -> RESET целевой платы
# 3. Залить загрузчик:
avrdude -c arduino -p atmega328p -P /dev/ttyUSB0 -b 19200 \
        -U flash:w:/usr/share/arduino/bootloaders/optiboot/optiboot_atmega328.hex:i \
        -U lock:w:0x0F:m
```

После этого:

1. `make flash BAUD=115200` — optiboot работает на этой скорости;
2. поставить `WATCHDOG_ENABLED` в `1` в `cfg_board.h`;
3. проверить по критерию приёмки из ADR-0022.

## Если что-то не собирается

| Сообщение | Причина |
|---|---|
| `avr-g++: command not found` | не установлен `gcc-avr` |
| `avr/io.h: No such file or directory` | не установлен `avr-libc` |
| `#error "F_CPU not defined"` | собирают файл напрямую, минуя Makefile |
| `region 'text' overflowed` | прошивка не влезла во флеш |
| `region 'data' overflowed` | не влезли статические данные: искать большие массивы |
| `avrdude: stk500_recv(): programmer is not responding` | не та скорость загрузчика: попробовать `BAUD=57600` и `BAUD=115200` |
| `avrdude: can't open device` | не тот порт или нет прав: `sudo usermod -aG dialout $USER` и перелогиниться |
