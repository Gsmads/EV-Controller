# EV Controller

Система управления детским электромобилем: прошивка контроллера на базе
ATmega328P, коммуникационный модуль на ESP32 и веб-интерфейс для настройки
и наблюдения.

**Статус:** ранняя разработка. Прошивка ни разу не запускалась на реальном
железе, известны блокирующие дефекты — см. [docs/AUDIT.md](docs/AUDIT.md).

---

## Идея

Обычный детский электромобиль — это кнопка «вперёд», кнопка «назад» и
радиопульт из коробки. Здесь вместо этого:

- **ребёнок управляет сам** — педали газа и тормоза, руль с электроусилителем,
  переключатели режимов на панели;
- **родитель наблюдает и вмешивается с телефона** — по WiFi, без радиопульта:
  притормозить, ограничить скорость, остановить. Телефон всегда под рукой,
  а браузер позволяет сделать полноценный интерфейс, а не три кнопки;
- **всё настраивается без перепрошивки** — максимальная скорость, отзывчивость
  педалей, кривые отклика, темп разгона, коэффициенты усилителя руля,
  пороги защиты по току;
- **машина не заводится без пароля** — защита от угона.

Ключевое решение в модели управления: педали родителя и педали ребёнка
работают **одновременно**, а не по принципу «или-или». Родитель подтормаживает —
машина замедляется; отпускает — ребёнок продолжает ехать с той скоростью, на
которую нажата его педаль. Как в машинках в игровом центре, где у оператора
есть пульт, но рулит ребёнок.

## Архитектура системы

Два физически разделённых блока, связанных шиной RS485.

```
┌────────────────────────────┐        ┌────────────────────────────┐
│  Блок 1 — связь (ESP32)    │        │  Блок 2 — движение (Nano)  │
│                            │ RS485  │                            │
│  · WiFi AP + STA           │◀══════▶│  · моторы задних колёс     │
│  · веб-интерфейс           │        │  · электроусилитель руля   │
│  · телеметрия по WebSocket │        │  · педали газа и тормоза   │
│  · связь с BMS по UART     │        │  · режимы движения         │
│  · свет, поворотники       │        │  · защита по току          │
│  · парктроники и ADAS      │        │  · телеметрия              │
│  · пароль, OTA             │        │                            │
└────────────────────────────┘        └────────────────────────────┘
```

**Почему два блока.** У ATmega328P не хватает ни пинов, ни памяти на всё сразу.
Периферия, не требующая жёсткого реального времени (свет, звук, парктроники,
веб), уходит на ESP32. За Arduino остаётся то, что обязано работать
детерминированно и не зависеть от WiFi: педали, моторы, руль, защита.

**Почему RS485.** Рядом с мощными DC-моторами обычный UART живёт плохо.
Дифференциальная линия с гальванической развязкой переносит помехи спокойно.

## Состав железа

| Блок | Компонент | Назначение |
|---|---|---|
| 1 | ESP32 | WiFi, веб, BMS, свет, парктроники |
| 2 | Arduino Nano (ATmega328P, 16 МГц) | контроллер движения |
| 2 | ZS-X11H ×2 | драйверы мотор-колёс, до 60 В / 350 Вт |
| 2 | BTS7960 (HW-039) | драйвер электроусилителя руля |
| 2 | HX711 + тензодатчик 1 кг | усилие на руле |
| 2 | ACS712-20A ×3 | ток моторов и усилителя |
| 2 | 74HC595 | дискретные сигналы драйверов |
| 2 | PCA9535 | входы панели, силовые реле |
| 2 | 6N137 ×8 | гальваническая развязка всех сигналов |
| 2 | ADM3491 + B1205S | изолированный RS485 с питанием по линии |

Плата контроллера разработана самостоятельно: полная гальваническая развязка
силовой части, ESD-защита на внешних линиях, кондиционирование аналоговых
входов, триггеры Шмитта на дискретных, ШИМ-драйверы реле с током удержания.
Разбор схемы — [docs/SCHEMATIC_ANALYSIS.md](docs/SCHEMATIC_ANALYSIS.md).

## Функциональность

### Реализовано (с оговорками, см. статус)

- чтение педалей: фильтрация, калибровка, мёртвая зона, кривые отклика
- плавный разгон и торможение с настраиваемым темпом
- профили режимов движения в EEPROM
- слоистая модель педалей: физические + виртуальные с комбинатором
- бинарный протокол UART с CRC16
- веб-дашборд: циферблат, графики, виртуальные педали

### Запланировано

**Движение**
- режимы: Locked, Neutral, Handbrake, Eco, Normal, Sport, Reverse, Parent
- безопасное переключение направления только через полную остановку
- настраиваемая частота ШИМ по режимам: ниже — момент на старте, выше — тишина
- защита по току с плавным ограничением, затем аварийным отключением
- электронный дифференциал: внутреннее колесо в повороте замедляется
- ABS-lite и traction control на существующих датчиках скорости
- круиз-контроль, плавный старт

**Руль**
- электроусилитель с PID: ребёнок прикладывает малое усилие, мотор помогает
- адаптивность: на скорости руль тяжелее, при парковке легче
- ограничение угла поворота на высокой скорости (анти-опрокидывание)

**Родительский контроль**
- виртуальные педали газа и тормоза поверх физических
- ограничение максимальной скорости на лету
- «родительский тормоз» — большая кнопка в приложении
- настраиваемая реакция на потерю связи: от «ничего» до «остановиться»
- геозона по GPS (если появится модуль)

**Периферия и помощь**
- фары, габариты, стоп-сигналы, поворотники, звуковой сигнал
- автоматические стоп-сигналы по темпу замедления
- автоповоротники по углу поворота руля
- парктроники: замедление при сближении с препятствием, подруливание,
  звук заднего хода с частотой по расстоянию

**Диагностика**
- телеметрия 10 Гц: скорость каждого колеса, токи, положение руля, педали
- одометр, журнал поездок, графики
- коды неисправностей с человекочитаемым описанием
- калибровка из веб-интерфейса, профили настроек

## Принципы

**Платформозависимый код — в одном файле.** Вся работа с регистрами
ATmega328P собрана в `hal_atmega328p.cpp`. Бизнес-логика не знает, на каком
микроконтроллере исполняется. Переезд на STM32 или ESP32 — замена одного файла.

**Функции Arduino не используются.** Ни `digitalWrite`, ни `analogRead`, ни
`millis` — вместо них собственные реализации на регистрах внутри HAL. Причина
та же: переносимость, плюс скорость и предсказуемость времени выполнения.

**Настройки живут в EEPROM, а не в коде.** Всё, что может понадобиться
подкрутить на площадке — калибровка, темп разгона, лимиты, коэффициенты —
меняется по UART из веб-интерфейса. Структура защищена CRC16 и версией.

**Безопасность закладывается аппаратно.** Любой выход, способный привести
машину в движение, имеет резистором заданный безопасный уровень на случай,
когда микроконтроллер молчит: при сбросе, при перепрошивке, при зависании.

**Никаких блокирующих задержек.** Кооперативный планировщик с фиксированными
интервалами, `delay()` запрещён.

## Быстрый старт

### Прошивка

Открыть `firmware/EV_Controller.ino` в Arduino IDE, плата Arduino Nano,
процессор ATmega328P. Все файлы в корне скетча компилируются автоматически.

> **Перед первым включением с моторами** прочитать
> [docs/HARDWARE_BRINGUP.md](docs/HARDWARE_BRINGUP.md) — раздел A-4.
> Без трёх резисторов на пинах ШИМ каждый сброс контроллера подаёт
> на моторы команду полной скорости.

### Веб-дашборд

```bash
cd tools/gui
pip install -r requirements.txt
python server.py            # автопоиск порта
```

Открыть <http://localhost:8000>.

### Тесты

```bash
cd tests && make run        # 71 тест, ~5 секунд
```
